## Standing gotchas for this codebase (worth remembering for future work)
1. **`build.js` strips every `class="..."` attribute** after inlining CSS via juice. Static markup gets its classes' styles baked into a `style=""` attribute first, so it's fine. Anything built by JS at *runtime* (table rows, dropdown menus, etc.) must use full inline styles — classes on dynamically-generated HTML do nothing.
2. **Two separate icon maps exist**: `build.js`'s (for static `<i data-ic="...">` markup) and the runtime `IC_` object (for `ico()`/`ico2()` calls in JS-generated HTML). An icon can exist in one and not the other — always check both when adding a new icon to dynamic content.
3. **`data-h="..."` hover styling works on both static and dynamic elements** — there's a generic `document`-level `mouseover`/`mouseout` delegated handler, not reliant on the (removed) stylesheet.
4. **Sticky `<th>` + unstyled `<tr>` = content bleed-through** on scroll. Any new table needs `position:relative;z-index:1` on its rows.
5. Functions/variables defined inside the main `<script>` are **not** on `window` — they're closed over by something (never fully traced what). Puppeteer tests must drive the UI via real clicks/DOM state, not call app functions directly through `page.evaluate`.
